    变量与数据抽象（Topics 3.1–3.2）

    知识点梳理（AAP-1.A / 1.B / 1.C / 1.D）

    （1）变量与赋值（AAP-1.A / 1.B）

    • 变量是程序中的抽象，同一时刻持有一个值（该值也可以是 list）。有意义的变量名提高可读性（AAP-1.A.2）。
    • 赋值运算符 ←：先求右侧表达式的值，再把一份副本赋给左侧变量（AAP-1.B.2）。
    • 变量保存的是最近一次赋的值（AAP-1.B.3）。经典陷阱：
    a ← 1
b ← a
a ← 2
DISPLAY(b)        // 仍然显示 1！b 拿到的是"当时 a 的值的副本"

    （2）list 与 string（AAP-1.C）

    • list 是有序元素序列，写作 [value1, value2, value3, ...]；element 是单个值，index 是引用元素的自然数编号。
    • AP CSP 伪代码中 list/string 的索引从 1 开始（AAP-1.D.8：索引小于 1 或超出元素个数会报错）。
    • string 是有序字符序列；字符串也有索引、也能 aString[i] 取字符。

    （3）数据抽象（AAP-1.D）

    • 数据抽象 = 把数据类型的抽象属性与其具体表示细节分离（AAP-1.D.1）。
    • 用 list 给一组相关数据起名字，程序更容易开发和维护（AAP-1.D.4）；list 中元素可以是不同类型（AAP-1.D.5）。
    • list 让多个相关项作为一个整体值处理；在不同语言里也叫 array。

    重难点

    赋值跟踪三步法（所有"代码段执行后变量值是多少"题的通用解法）：

    1. 画一张变量表（variable trace table），列出每个变量。

    2. 逐行执行，每行只更新表中对应变量，其余保持不变。

    3. 注意右侧先全部求值再赋值——a ← b 不会让 a、b 之后保持联动。

    易混：a ← b vs a ← b + 1：前者复制值；后者先计算再复制。AP 不会考"引用 vs 值"的深层语义，只考"副本"这一层。

    易错点

    • ❌ 以为 b ← a 后 b 会跟着 a 变。正确：赋值只复制当时的值。
    • ❌ 把 list 索引当从 0 开始（Python/Java 习惯）。AP 伪代码从 1 开始，aList[1] 是第一个元素。
    • ❌ 认为 list 必须同类型。AP 允许混合类型（数字、字符串、布尔可共存）。
    • ❌ 数据抽象题只答"让代码更短"。标准答案要点：给数据集合命名 → 无需了解内部表示 → 易于开发与维护。

    表达式、布尔与条件（Topics 3.3–3.7）

    知识点梳理（AAP-2.A–2.I）

    （1）算术运算（AAP-2.C）

    • 运算符：+、-、、/、MOD（取余）。运算优先级与数学相同，MOD 与 / 同级（AAP-2.C.4）。
    • a MOD b：a 除以 b 的余数（a ≥ 0，b > 0）。例：17 MOD 5 = 2；n MOD 2 = 0 即 n 是偶数（最高频用法）；n MOD 10 取个位。

    （2）字符串操作（AAP-2.D）

    • concat(str1, str2)：把两个字符串首尾相连成新串。
    • substring(str, start, length)：从第 start 个字符（索引从 1 开始！）起取 length 个字符。例：substring("delivery", 3, 4) 返回 "live"。

    （3）布尔表达式（AAP-2.E / 2.F）

    • 关系运算符：= ≠ > < ≥ ≤，结果为 true/false。
    • 逻辑运算符（全部大写）：NOT、AND、OR。
    • NOT：真假取反。
    • AND：两者都 true 才 true。
    • OR：至少一个 true 即 true。

    逻辑运算真值表（必背）：

    ABA AND BA OR BNOT A
    truetruetruetruefalse
    truefalsefalsetruefalse
    falsetruefalsetruetrue
    falsefalsefalsefalsetrue

    重要恒等式（2025 真题直接考过）：

    • (A AND true) = A；(A AND false) = false
    • (A OR true) = true；(A OR false) = A
    • NOT(A AND B) = (NOT A) OR (NOT B)；NOT(A OR B) = (NOT A) AND (NOT B)（德摩根律）

    （4）条件语句 IF / IF-ELSE（AAP-2.G / 2.H）

    IF(condition)
{
    <statements>       // condition 为 true 时执行
}

IF(condition)
{
    <statements1>      // true 时执行
}
ELSE
{
    <statements2>      // false 时执行
}

    （5）嵌套条件（AAP-2.I）：条件里套条件。ELSE 与最近的未配对 IF 配对。三档判断（如 >15 Platinum / >5 Gold / 否则 Basic）既可写成嵌套 IF-ELSE，也可写成两个并列 IF——两种写法是否等价要看条件是否互斥。

    重难点

    IF-ELSE 与布尔表达式的互化（AAP-2.L.3/4，真题高频）：

    IF(x = 5)  { y ← true }  ELSE  { y ← false }
// 等价于
y ← (x = 5)

    多重 IF-ELSE 等价性判断技巧：给每个变量代入边界值（如 5、15、16）逐个测试选项。2025 Q68（reward level）和 2026 Q33（highest score）都是"代入边界值 + 跟踪流程"就能解决的。

    "x 但不同时 y"（XOR）写法：(x AND (NOT y)) OR (y AND (NOT x))；两变量一正一负：(q > 0) XOR (r > 0) 等价于 ((q > 0) AND (r ≤ 0)) OR ((r > 0) AND (q ≤ 0))。注意"正数"要写成 > 0，"非正"是 ≤ 0 而不是 < 0。

    易错点

    • ❌ substring 用 0 起始索引。AP 从 1 开始："delivery" 第 3 个字符是 "l"。
    • ❌ MOD 优先级低于乘除。同级，从左到右算。
    • ❌ 把 (A AND true) 化简成 true。应化简为 A。
    • ❌ 忽略 IF 无 ELSE 时的"不执行任何分支"情况——条件为 false 时直接跳过，变量保持原值。
    • ❌ 嵌套 IF 中 ELSE 配对错误。配最近的 IF。
    • ❌ 边界混淆：≥ 16 与 > 16 差一个值。题目说 "at least 16" 就是 ≥ 16。

    迭代与算法开发（Topics 3.8–3.9）

    知识点梳理（AAP-2.J–2.M）

    （1）迭代（AAP-2.J / 2.K）

    • Iteration：算法中重复执行的部分——重复指定次数或直到条件满足。
    • REPEAT n TIMES { ... }：执行恰好 n 次。
    • REPEAT UNTIL(condition) { ... }：先检查条件，后执行循环体；条件为 true 时停止（不是"为 true 时执行"）。
    • 若一开始条件就为 true，循环体一次都不执行（AAP-2.K.5）。
    • 若条件永远不为 true → 死循环（infinite loop）（AAP-2.K.4）。

    （2）开发算法（AAP-2.L / 2.M）

    • 同一任务可以由不同算法完成；看起来相似的算法可能产生不同结果/副作用（AAP-2.L.2）。
    • 某些条件语句可写成等价布尔表达式，反之亦然。
    • 算法的来源：从想法构造、组合现有算法、修改现有算法（AAP-2.M.1）。
    • 必会的"积木算法"（AAP-2.M.2 / 2.O.4，几乎每年考）：
    • 求最大/最小值；求和/平均值；
    • 计数（counting）：满足条件的元素个数；
    • 线性/顺序查找（linear/sequential search）：逐个检查直到找到或查完。

    重难点

    REPEAT UNTIL 跟踪模板：

    n ← 1
REPEAT UNTIL(n > 4)
{
    DISPLAY(n)
    n ← n + 1
}
// 输出：1 2 3 4（n=5 时条件成立，退出）

    判断输出几行/循环几次：列出每轮的 n 与条件真值，数到条件第一次为 true 为止。

    死循环识别三特征：① 循环体内没有改变条件中变量的语句；② 变量朝错误方向变（如条件 n < 5 而 n 每次 -1）；③ 条件写成恒假（如 REPEAT UNTIL(false)）。

    计数算法标准模板：

    count ← 0
FOR EACH item IN aList
{
    IF(条件)
    {
        count ← count + 1
    }
}
DISPLAY(count)

    易错点

    • ❌ 把 REPEAT UNTIL 当"直到条件为 true 才执行"。每次迭代先检查，true 就停。
    • ❌ 循环体边界差一：REPEAT 3 TIMES 里 n ← n + 1 从 n=1 开始，结束时 n = 4（不是 3）。
    • ❌ 死循环题选"再等一会儿就好"。条件写错就是永远不终止。
    • ❌ 认为"看起来像的算法结果一样"（AAP-2.L.2 反例年年出）。
    • ❌ 求最大值算法忘记把 max 初始化为第一个元素（初始化为 0 在全负数列表会错）。

    列表与搜索（Topics 3.10–3.11）

    知识点梳理（AAP-2.N–2.P）

    （1）list 操作（AAP-2.N）

    • aList[i]：访问索引 i 的元素（从 1 开始）。
    • APPEND(aList, value)：把 value 加到列表末尾。
    • REMOVE(aList, i)：删除索引 i 的元素，后面元素整体前移，列表长度 -1。
    • INSERT(aList, i, value)：在索引 i 处插入 value（原 i 及之后后移）。
    • LENGTH(aList)：元素个数。
    • FOR EACH item IN aList { ... }：完整遍历——item 依次取每个元素的值（不是索引）；遍历时修改列表长度是高危操作。

    （2）列表遍历算法（AAP-2.O）

    • 完整遍历 vs 部分遍历（AAP-2.O.1）：全部访问 vs 只访问一段。
    • 常用积木算法：求最大/最小、求和/平均、计数、线性查找（逐个检查直到找到或查完）。

    （3）二分查找（AAP-2.P）

    • 前提：数据必须已排序（AAP-2.P.2）！
    • 流程：从中间元素开始比较 → 若目标更大，舍弃较小的一半；若更小，舍弃较大的一半 → 重复直到找到或区间为空（AAP-2.P.1）。
    • 效率：对已排序数据，二分通常远快于线性查找（AAP-2.P.3）。
    • 核心计算：n 个元素最多检查 ⌈log₂(n+1)⌉ 次左右（约 log₂n 量级）：
    • 100 个元素 → 约 7 次（2⁷ = 128）
    • 500 个元素 → 9 次（2⁹ = 512；2⁸ = 256 < 500）→ CED 样题 Q13 答案 A(10) 与此一致，按"最接近"取 10
    • 1000 个元素 → 约 10 次
    • 100 万个元素 → 约 20 次

    重难点

    APPEND/REMOVE 组合跟踪（2025 Q22 原题套路）：

    listA ← ["Red", "Green", "Orange"]
listB ← ["Purple", "Blue", "Yellow"]
APPEND(listB, listA[1])        // listB 末尾加 "Red"
REMOVE(listA, 1)               // listA 删掉 "Red"，其余前移
// 结果：listA = ["Green", "Orange"]
//        listB = ["Purple", "Blue", "Yellow", "Red"]

    遍历中删除元素（2025 Q64 高危套路）：在 REPEAT UNTIL / FOR EACH 中 REMOVE(aList, index) 后，被删位置换上了新元素——若继续 index ← index + 1 会跳过一个元素；正确做法之一是删除后 index ← index - 1（或多选答案里选"删后不前进/回退"的选项）。

    二分 vs 线性选择判断：题目给"未排序的列表" → 只能线性；给"已排序 + 要求最快" → 二分；问"二分查找的前提" → 数据必须有序。

    易错点

    • ❌ 索引从 0 开始。AP 从 1 开始，且越界会报错。
    • ❌ FOR EACH x IN listX 中把 x 当索引用（2025 Q51 A 选项陷阱：listX[x] 错误；x 就是元素值）。
    • ❌ REMOVE 后索引前进导致漏查/越界。
    • ❌ 二分查找用于未排序数据。先排序才能二分。
    • ❌ 二分次数心算错：记对半砍——500 → 250 → 125 → 63 → 32 → 16 → 8 → 4 → 2 → 1，共约 9~10 次区间缩小。

    过程、库、随机与模拟（Topics 3.12–3.16）

    知识点梳理（AAP-3.A–3.F）

    （1）过程调用（AAP-3.A）

    • Procedure（过程）：命名的指令组，可有参数（parameters）与返回值；不同语言叫 method / function。
    • 参数 vs 实参：参数是过程定义里的输入变量；arguments（实参）是调用时给出的具体值（AAP-3.A.3）。
    • 过程调用会打断顺序执行，执行过程内语句，到 RETURN 或结尾后回到调用点继续（AAP-3.A.4）。
    • DISPLAY(expr) 显示值后跟一个空格；RETURN(expr) 返回控制权与值；INPUT() 接收用户输入。
    • DISPLAY 只是打印；RETURN 才有"值"——DISPLAY(sum(a,b)) 与直接 DISPLAY(a+b) 效果相同，但 x ← sum(a,b) 必须过程有 RETURN。

    （2）过程抽象（AAP-3.B / 3.C）

    • 过程抽象：给一段处理流程起名字，使用者只需知道做什么、不必知道怎么做（AAP-3.B.1）。
    • 大问题拆成子问题、每个子问题写一个过程 = 模块化（modularity）（AAP-3.B.2/3）。
    • 抽象共享特征 → 代码复用 → 管理复杂度；参数化让过程可适用一组输入（AAP-3.B.4/5）。
    • 好处：提高可读性；可以改内部实现而无需通知使用者（AAP-3.B.6/7）。

    （3）库（AAP-3.D）

    • Library：包含可在新程序中使用的过程集合；简化复杂程序开发（AAP-3.D.1/3）。
    • 现有代码可来自内部或外部来源（AAP-3.D.2）。
    • API：说明库中过程的行为与用法的规范；读 API 文档才能正确使用库（AAP-3.D.4/5）。

    （4）随机值（AAP-3.E）

    • RANDOM(a, b)：生成 a 到 b 之间（含两端） 的随机整数，每个值等可能。
    • 取值个数 = b − a + 1（高频计算！）：RANDOM(1,4) 有 4 种；RANDOM(2,5) 有 4 种。
    • 使用随机数 → 每次运行程序结果可能不同（AAP-3.E.2）。

    （5）模拟（AAP-3.F）

    • Simulation：为特定目的对复杂对象/现象做的抽象表示（AAP-3.F.1）；用随时间变化的值反映现象状态。
    • 用途：在不便做真实实验时（太大、太小、太快、太慢、太贵、太危险）研究现象、推导与修正假设（AAP-3.F.6/7）。
    • 开发模拟要去掉细节、简化功能；因此可能包含偏差（选取/排除哪些真实元素）（AAP-3.F.4/5）。
    • 随机数生成器用来模拟现实世界的随机变化（AAP-3.F.8）。

    重难点

    含 RANDOM 的代码段结果判断：把 RANDOM 的每一个可能取值代入跟踪一遍，看哪些选项的输出"可能"出现（问 possible）或"一定"出现（问 must）。2026 Q16（机器人随机走）与 2025 Q47（抛 5 枚硬币）都是此套路。

    过程组合（2026 Q54 isPerfect 套路）：

    PROCEDURE sumFactors(number)  { ... RETURN(s) }
PROCEDURE isPerfect(number)
{
    sum ← sumFactors(number)
    RETURN(sum - number)
}

    调用 isPerfect(28)：先执行 sumFactors(28) 得 28 的因数和，再减 28。嵌套调用逐层展开即可。

    易错点

    • ❌ RANDOM(2,5) 以为有 5 个值。含两端，5−2+1 = 4 个。
    • ❌ 混淆 DISPLAY 与 RETURN。没有 RETURN 的过程不能给变量赋"计算结果"。
    • ❌ 模拟题答"模拟完全等于现实"。模拟是抽象，必有简化与偏差。
    • ❌ 模拟适用场景选错。关键词：impractical（不现实）——太大/太小/太快/太慢/太贵/太危险。
    • ❌ 认为 API 与库无关。API 就是库的使用说明书。

    算法效率与可判定性（Topics 3.17–3.18）

    知识点梳理（AAP-4.A / 4.B）

    （1）问题与效率（AAP-4.A）

    • Problem（问题）是对任务的一般性描述；instance（实例）包含具体输入。例：排序是 problem；给 [7, 3, 9, 1] 排序是 instance。
    • Decision problem（判定问题）：答案为 yes/no（如"从 A 到 B 有路径吗？"）；Optimization problem（优化问题）：找"最好"解（如"最短路径是什么？"）（AAP-4.A.2）。
    • Efficiency（效率）：算法所用计算资源的估计，通常表示为输入规模 n 的函数；可通过形式化或数学推理确定，也可非正式地数语句执行次数（AAP-4.A.3/4/5）。
    • 不同正确算法效率可以不同（AAP-4.A.6）。

    （2）reasonable time（AAP-4.A.7）

    效率类型例子分类
    常数、线性、平方、立方（多项式及更慢）1 次遍历、双层循环Reasonable time
    指数、阶乘2ⁿ 种子集枚举、n! 排列Not reasonable time

    （3）Heuristic（启发式）（AAP-4.A.8/9）

    • 有些问题没有已知的高效算法——无法在合理时间内保证最优解。
    • Heuristic：不保证最优（甚至不保证正确），但在实际中"够用"的近似解法。使用场景：最优算法不切实际（impractical）时。
    • 经典例子：地图导航走"看起来近"的路、下棋 AI 只往前看若干步。

    （4）可判定性（AAP-4.B）

    • Decidable problem：存在算法能对所有输入给出正确 yes/no 答案（如"这个数是偶数吗？"）（AAP-4.B.1）。
    • Undecidable problem：不存在总能给出正确 yes/no 回答的算法（AAP-4.B.2）。
    • 关键理解（最高频考点）：undecidable 问题可能有一些实例可以被算法解决，但没有任何算法能解决它的所有实例（AAP-4.B.3）。所以"某算法对一些实例给出解、对另一些实例永远给不出解"与"问题 undecidable"完全相容——2025 Q47 正是考这一点。

    重难点

    "reasonable time" 判断口诀：看循环嵌套层数与输入的关系——

    • 单层遍历所有输入 → 线性 → reasonable。
    • 两两比较所有配对（双层循环）→ 平方 → reasonable。
    • 枚举所有子集（2ⁿ）或所有排列（n!）→ not reasonable。

    heuristic vs undecidable 辨析（2025 Q47 干扰项设置）：

    • 算法有时能给解、有时永远给不出，且无逻辑错误 → 问题本身 undecidable（选 undecidable，不选 heuristic）。
    • heuristic 是"为了速度放弃最优"，与"能不能解出"无关。

    "某算法解决了所有实例吗"三选一：

    1. 若问题 decidable 且算法无逻辑错误 → 能。

    2. 若问题 undecidable → 不存在这样的算法，任何算法都不行。

    3. 题目说"算法对某些实例无解"→ 说明问题 undecidable（或算法不完备，看题干暗示）。

    易错点

    • ❌ 把 undecidable 理解成"还没找到算法"。是数学上证明了不存在。
    • ❌ 认为 undecidable 问题的所有实例都无解。部分实例可有解（AAP-4.B.3）。
    • ❌ 把平方效率当成 not reasonable。多项式及以下都 reasonable。
    • ❌ optimization 与 decision problem 混为一谈。一个是"最好解"，一个是"yes/no"。
    • ❌ 见到"慢"就选 not reasonable。判据是增长率（多项式 vs 指数/阶乘），不是绝对速度。

    重难点与易错点速查表（考前 10 分钟过一遍）

    1. 赋值是复制值：b ← a 后 a 变 b 不变。

    2. list/string 索引从 1 开始；越界报错。

    3. MOD 与 * / 同级；n MOD 2 = 0 判偶数。

    4. substring(s, start, len) 的 start 从 1 数。

    5. (A AND true) = A；(A OR false) = A；德摩根律两条。

    6. REPEAT UNTIL 先判后做；条件一开始为 true 则循环体执行 0 次。

    7. 死循环 = 条件永远不为 true = 条件变量没被正确更新。

    8. RANDOM(a,b) 含两端，取值个数 = b−a+1。

    9. FOR EACH 的变量是元素值不是索引。

    10. REMOVE 后元素前移，遍历删除要回退索引或小心前进。

    11. 二分查找前提：已排序；n 个元素最多约 log₂n 次（500→约 9~10 次）。

    12. 无 RETURN 的过程不能给变量赋计算结果；DISPLAY 只是打印。

    13. 参数在定义处；arguments 是调用处给的实参。

    14. 库 + API 文档 = 简化复杂程序开发。

    15. 模拟 = 抽象 + 简化 → 必有偏差；适用场景 = 现实实验 impractical。

    16. 多项式效率 = reasonable；指数/阶乘 = not reasonable。

    17. Heuristic = 不保证最优的近似解，用于最优解不切实际时。

    18. Undecidable = 不存在对所有输入都正确的算法；但部分实例可以有解。

    • Row 7（Algorithm Implementation - Sequencing/Selection/Iteration）：说明程序中某算法如何同时使用顺序、选择、迭代三种结构。
    • Row 8（Algorithm Testing）：给出两组具体调用，说明程序在不同输入下产生的不同结果。

    得分要点（对照 scoring guidelines）

    1. 描述过程时先写"它做什么"（what）再写"它怎么做"（how）——这正是过程抽象的定义。

    2. 调用语句必须真实出现在你的程序代码截图里，实参值写具体。

    3. "算法使用了三种结构"必须逐一对号入座：顺序（语句按序执行）、选择（IF/ELSE）、迭代（REPEAT/FOR EACH），并指出各自的代码位置。

    4. 测试题要写两个不同的输入和对应的不同输出，最好一组触发 IF 的 true 分支、一组触发 false 分支。

    题型分布与时间分配

    Big Idea 3 在 MCQ 中约占 13–15 题（42 题中），其中：

    • 代码跟踪题（变量/IF/循环/过程调用）约 5–7 题 → 每题 ≤ 1.5 分钟

    • 概念题（效率/模拟/undecidable/库）约 3–4 题 → 每题 ≤ 1 分钟

    五大高频套路（考前最后过一遍）

    1. 变量表跟踪法：任何"代码段输出"题先画表逐行填。赋值是复制，FOR EACH 的变量是元素值，索引从 1 开始。

    2. REPEAT UNTIL 先判后做：条件一开始为 true 就执行 0 次；条件变量必须被循环体更新，否则死循环。

    3. 遍历找反例：判断"所有元素都…"→ 遇到反例立即断言 false，查完无反例才 true。只看首尾元素永远不够。

    4. 二分查找三件套：已排序；每次砍半；次数 ≈ log₂n（100→7、500→9、1000→10）。

    5. undecidable ≠ 慢：undecidable 是"不可能有算法解决所有实例"；not reasonable time 是"有算法但跑不完"。两个概念从不混用，选项里出现另一个就是干扰。

    赋值、显示与输入（Assignment, Display, and Input）

    指令（Text）官方解释
    a ← expression先求 expression 的值，再把结果的一份拷贝赋给变量 a
    DISPLAY(expression)显示 expression 的值，后跟一个空格
    INPUT()接受用户输入的一个值，并返回该输入值

    算术运算符（Arithmetic Operators and Numeric Procedures）

    指令（Text）官方解释
    a + b / a - b / a * b / a / b加、减、乘、除四则运算；例如 17 / 5 求值为 3.4；求值时适用数学运算优先级
    a MOD ba 除以 b 的余数。假定 a 为 ≥ 0 的整数、b 为 > 0 的整数；例如 17 MOD 5 求值为 2；MOD 与 *、/ 同优先级
    RANDOM(a, b)生成并返回 a 到 b 之间（含 a 和 b 两端）的随机整数，每个结果等可能；例如 RANDOM(1, 3) 可能返回 1、2 或 3

    关系与布尔运算符（Relational and Boolean Operators）

    指令（Text）官方解释
    a = b / a ≠ b / a > b / a < b / a ≥ b / a ≤ b关系运算符：测试两个变量、表达式或值之间的关系，结果为布尔值。例如 a = b 在 a 与 b 相等时求值为 true，否则为 false
    NOT conditioncondition 为 false 时求值为 true；否则求值为 false
    condition1 AND condition2两个条件都为 true 时才为 true；否则为 false
    condition1 OR condition2条件 1 为 true、或条件 2 为 true、或两者都为 true 时为 true；否则为 false

    选择（Selection）

    指令（Text）官方解释
    IF(condition) { <block of statements> }布尔表达式 condition 为 true 时执行块内代码；为 false 时不采取任何行动
    IF(condition) { <first block> } ELSE { <second block> }condition 为 true 时执行 first block；否则执行 second block

    迭代（Iteration）

    指令（Text）官方解释
    REPEAT n TIMES { <block of statements> }块内代码执行 n 次
    REPEAT UNTIL(condition) { <block of statements> }重复执行块内代码，直到布尔表达式 condition 求值为 true

    列表操作（List Operations）

    官方总注：所有列表操作中，若列表索引小于 1 或大于列表长度，产生错误信息且程序终止。列表索引从 1 开始（与多数真实语言不同，考试时按此算）。

    指令（Text）官方解释
    aList ← [value1, value2, value3, ...]创建新列表，value1、value2、value3… 依次存于索引 1、2、3…，并赋给 aList
    aList ← []创建空列表并赋给 aList
    aList ← bList把 bList 的一份拷贝赋给 aList。例如 bList 含 [20, 40, 60]，赋值后 aList 也含 [20, 40, 60]
    aList[i]访问 aList 索引 i 处的元素。第一个元素在索引 1，用 aList[1] 访问
    x ← aList[i]把 aList[i] 的值赋给变量 x
    aList[i] ← x把 x 的值存入 aList[i]
    aList[i] ← aList[j]把 aList[j] 的值存入 aList[i]
    INSERT(aList, i, value)索引 ≥ i 的元素整体右移一位；长度加 1；value 放入索引 i 处
    APPEND(aList, value)长度加 1，value 追加到 aList 末尾
    REMOVE(aList, i)移除 aList 索引 i 处的元素，其后元素左移；长度减 1
    LENGTH(aList)求值为 aList 的元素个数
    FOR EACH item IN aList { <block of statements> }变量 item 依次取 aList 的每个元素（从第一个到最后一个，按顺序），每取一次执行一遍块内代码

    过程定义与调用（Procedures and Procedure Calls）

    指令（Text）官方解释
    PROCEDURE procName(parameter1, parameter2, ...) { <block of statements> }定义过程 procName：接受零或多个参数，过程体为 block of statements
    procName(arg1, arg2, ...)调用过程：arg1 赋给 parameter1，arg2 赋给 parameter2……依次对应
    PROCEDURE procName(parameter1, parameter2, ...) { <block of statements> RETURN(expression) }定义带返回值的过程：过程体含 block of statements 并返回 expression 的值
    result ← procName(arg1, arg2, ...)调用过程，并把返回值赋给变量 result
    RETURN(expression)控制流立即返回到调用该过程的位置，并返回 expression 的值。RETURN 可出现在过程体内任意位置，一旦执行即立即返回

    官方总注：若机器人试图移动到一个非开放格子或网格边缘之外，机器人停留在原位置，程序终止。
